## 二、自检问答

**Q1. `always @(posedge clk)` 里为什么用 `<=` 而不是 `=`？**
非阻塞赋值的右边读的是本拍开始时的旧值，所有寄存器"同时"更新，描述的是并行硬件。
用阻塞 `=` 会让块内语句产生先后依赖（软件语义），多个寄存器之间互相串值。

**Q2. 同步复位还是异步复位？为什么三个模块要一致？**
本项目三个模块统一用**异步低有效复位**（`always @(posedge clk or negedge rst_n)`）。
好处是复位不需要时钟，上电/异常时立即可靠；代价是复位释放要对齐时钟沿（否则有恢复/移除时间风险）。
三个模块一致，是为了将来把它们拼成流水线时复位行为可预测。

**Q3. FIFO 的"满"和"空"怎么区分？为什么不用指针直接比？**
用**计数法**：`empty = (cnt==0)`、`full = (cnt==DEPTH)`。指针直接比（`wptr==rptr`）无法区分
"空"和"整圈绕回来刚好相等"两种情况，必须多存一位（指针法），或用计数器消歧。

**Q4. 为什么这个 FIFO 没占 Block RAM，而是 LUT 里的分布式 RAM？**
深度只有 16、位宽 8（共 128 bit）。BRAM 最小粒度是 18 Kb，用它装 128 bit 太浪费；
综合器于是把它推断成 `RAM32M`（分布式 RAM，用 LUT 实现，报告里体现为 `LUT as Memory = 8`）。
深度大到几百以上、或者要求高带宽/低功耗时，才会主动例化 BRAM。

**Q5. LIF 里 `en = 0` 时保持不动，为什么能省电？`en` 在真实系统里由谁驱动？**
CMOS 动态功耗 ≈ αCV²f，翻转率 α 是关键项。`en = 0` 时该神经元的 16 个触发器一个都不翻转，
只有组合逻辑的极小漏电，动态功耗接近 0。真实系统里 `en` 由**事件（脉冲）**驱动：
只有 AER 总线上真的来了一个 spike，对应神经元的那一拍才更新——这就是"事件驱动"相对
"时钟驱动、每拍全阵列更新"的能效来源。

**Q6. 握手寄存器里，为什么 `s_ready` 可以组合产生，而 `m_valid` 不行？**
`ready` 是**反向**的许可信号，必须当拍直通：若打成寄存器，下游"我能收"要晚一拍才传回上游，
每笔传输多耗一拍，吞吐砍半。`valid` 与数据**同向**前进，必须和 `m_data` 一起被切一拍，
否则上游的组合逻辑会穿过本模块直捅下游，形成贯穿多级模块的长路径，时序必崩。
（综合结果印证：`m_valid` 是 FDCE，`m_data` 是 8 个 FDRE；`s_ready` 只占 1 个 LUT2。）
